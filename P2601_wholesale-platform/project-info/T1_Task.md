## 当前阶段规划：商品主图字段 MVP 搭建

创建时间：2026-06-29

阶段目标：

```text
先打通商品主图从卖家录入、后端保存、数据库落点，到卖家端、管理端、买家端展示的最小闭环。
```

阶段边界：

```text
本阶段先用图片 URL 作为商品主图，不做真实图片上传。
真实上传的最终结果也是生成一个可访问的图片 URL，后续再单独升级。
```

### 1. 数据库层：主图字段落点

- [ ] 在 `product` 表增加 `main_image_url` 字段。
- [ ] 将字段同步到 `development/database/init.sql`。
- [ ] 将字段说明同步到 `development/database/tables.md`。
- [ ] 在 DBeaver 中确认本机数据库已经有主图字段。

### 2. 后端层：接口支持主图字段

- [ ] 新增商品时，后端可以接收主图 URL。
- [ ] 商品保存时，主图 URL 可以写入 `product.main_image_url`。
- [ ] 查询商品时，后端可以把主图 URL 返回给前端。
- [ ] 确认原有审核、上架、买家可见规则不受影响。

### 3. 卖家端前端层：录入与管理主图

- [ ] 卖家新增商品时可以填写主图 URL。
- [ ] 卖家商品列表可以看到商品主图。
- [ ] 没有主图的商品有基础占位展示。

### 4. 管理端联动：审核时查看主图

- [ ] 管理端待审核列表可以看到商品主图。
- [ ] 管理员可以结合商品名称、类目、价格和主图进行基础判断。
- [ ] 审核通过或拒绝后，原有状态流转保持不变。

### 5. 买家端联动：展示带图商品

- [ ] 买家端商品列表可以展示商品主图。
- [ ] 买家端仍然只展示已上架、已审核、有库存的商品。
- [ ] 商品列表从纯文字展示升级为更接近电商商品卡片的展示。

### 6. 联调验证

- [ ] 卖家新增一条带主图 URL 的商品。
- [ ] 回到 DBeaver 查看 `main_image_url` 是否保存成功。
- [ ] 管理端审核该商品。
- [ ] 卖家端将审核通过的商品上架。
- [ ] 买家端确认该商品和主图可以正常展示。

### 阶段结果

本阶段完成后，预期跑通：

```text
卖家新增带主图商品
  -> 数据库保存 main_image_url
  -> 管理端审核时看到主图
  -> 卖家上架商品
  -> 买家端看到商品主图
```

暂缓项：

- 真实图片上传。
- 对象存储或 CDN。
- 多张商品图。
- 商品详情页。
- 询盘或下单入口。
- 商品信息维护与审核联动。

暂缓原因：

```text
当前重点是理解商品图片字段如何穿过数据库、后端接口和三端页面。
等主图字段 MVP 跑通后，再继续做商品信息维护、商品详情页或真实图片上传。
```

## 下一阶段候选规划：商品信息维护与审核联动

阶段目标：

```text
让卖家可以维护商品信息，同时让平台能控制哪些修改需要重新审核，哪些修改可以直接生效。
```

建议把“修改商品信息、下架 / 重新上架、修改后重新审核”合并成一个阶段处理。

### 1. 商品编辑能力

- [ ] 卖家可以编辑商品名称、类目、主图、价格、库存、起批量等信息。
- [ ] 编辑后卖家端商品列表能看到最新信息。
- [ ] 买家端只能看到符合可见规则的商品。

### 2. 修改字段分类

需要重新审核的内容类字段：

- 商品名称。
- 商品类目。
- 商品主图。
- 后续的商品描述、详情图等内容。

可以直接生效的经营类字段：

- 价格。
- 库存。
- 起批量。

### 3. 审核联动规则

内容类字段发生变化时：

```text
商品自动下架
  -> status 变为 OFF_SHELF
  -> audit_status 变为 PENDING
  -> 管理端重新审核
  -> 审核通过后卖家再手动上架
```

经营类字段发生变化时：

```text
不改变 audit_status
不强制下架
直接更新价格、库存、起批量
```

### 阶段结果

本阶段完成后，预期跑通：

```text
卖家修改商品内容类信息
  -> 商品重新进入待审核
  -> 管理端审核
  -> 卖家重新上架

卖家只修改价格、库存、起批量
  -> 信息直接更新
  -> 商品保持原有审核和上下架状态
```
