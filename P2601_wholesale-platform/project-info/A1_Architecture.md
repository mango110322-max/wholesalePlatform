# A1_Architecture

## 产品参照与设计目标

本项目目标是从 0 到 1 搭建一个服装批发 B2B 电商产品，并串联买家端、卖家端、管理端的产品逻辑。

LIUHUAMALL 和过往 PRD 作为案例资料，用于参考真实项目的思考方式和业务拆解方式，不作为当前项目的功能蓝本。

设计重点：

- 从目标用户、采购场景和供货场景出发，逐步推导买家端、卖家端、管理端能力。
- 从买卖双方的业务动作出发，补齐管理端类目、审核、用户和基础监管能力。
- 让每个页面设计都能回答“它服务哪个角色、依赖哪些数据、由哪个后台能力支撑”。

## 业务关键构成

服装批发平台由三个主要使用端构成：

| 使用端 | 主要用户 | 核心目的 | 初始功能模块 |
| --- | --- | --- | --- |
| 买家端 | buyer、采购人员 | 发现商品、联系卖家、完成采购相关动作 | 商品浏览、搜索筛选、商品详情、询盘、下单、个人中心 |
| 卖家端 | seller、商家/供应商 | 上架商品、管理商品、处理采购需求 | 商品上架、商品管理、库存/价格管理、询盘处理、订单管理 |
| 管理端 | 平台运营人员 | 管理买家、卖家、商品与平台运营秩序 | 买家管理、卖家管理、商品审核、类目管理、订单/询盘监管 |

## 业务角色

| 角色 | 主要诉求 | 典型动作 |
| --- | --- | --- |
| 买家 | 快速找到合适货源，确认价格、库存、起批量和供货能力 | 浏览商品、筛选类目、查看详情、发起询盘、提交订单 |
| 卖家 | 展示商品并高效处理采购需求 | 发布商品、维护价格库存、回复询盘、处理订单 |
| 平台运营 | 维护平台商品质量、交易秩序和基础数据 | 审核商品、管理类目、管理买卖双方、监管询盘和订单 |

## 核心业务对象

| 业务对象 | 说明 | 关联关系 |
| --- | --- | --- |
| 买家 | 发起采购需求的一方 | 可发起询盘、创建订单 |
| 卖家 | 提供服装货源的一方 | 可发布商品、处理询盘和订单 |
| 商品 | 平台展示和交易的核心内容 | 归属卖家，关联类目、价格、库存、起批量 |
| 类目 | 商品组织和筛选的基础结构 | 管理端维护，买家端用于浏览筛选 |
| 询盘 | 买家向卖家发起的采购沟通 | 由买家创建，卖家处理，可转化为订单 |
| 订单 | 买卖双方达成采购意向后的履约记录 | 关联买家、卖家、商品、价格和数量 |

## 核心业务流程

| 流程 | 主要步骤 | 涉及端 |
| --- | --- | --- |
| 商品发布 | 卖家创建商品 -> 设置类目、图片、价格、库存、起批量 -> 平台审核 -> 商品上架 | 卖家端、管理端 |
| 找货采购 | 买家浏览/搜索商品 -> 筛选合适货源 -> 查看商品详情 -> 发起询盘或下单 | 买家端 |
| 询盘处理 | 买家提交采购需求 -> 卖家查看并回复 -> 双方确认价格、数量、交期等信息 | 买家端、卖家端 |
| 订单管理 | 买家提交订单 -> 卖家处理订单 -> 平台监管订单状态和异常 | 买家端、卖家端、管理端 |
| 平台治理 | 平台维护类目 -> 审核商品 -> 管理用户 -> 处理违规或异常业务记录 | 管理端 |

## 业务设计原则

- 先围绕买家找货、卖家供货、平台治理三条主线展开。
- 优先完成商品、询盘、订单三类核心业务闭环。
- 管理端先服务基础审核和秩序维护，不一开始追求复杂运营能力。
- 后续页面、数据对象和接口设计都围绕业务流程逐步拆解。

## 后续架构内容

后续会继续细化买家端、卖家端、管理端下的页面结构、功能流程、数据对象和接口关系。
