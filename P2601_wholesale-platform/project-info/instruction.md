# instruction

## 文档定位

`instruction.md` 用于记录当前项目结构的使用说明、编号规则和协作约定。

具体模块文件只记录对应内容本身：

- `I1_Index.md` 只负责索引和查找入口。
- `A1_Architecture.md` 只负责业务架构。
- `L1_Log.md` 只负责记录项目日志。
- `Plan.md` 只负责目标、介绍和推进步骤。
- `T1_Task.md` 只负责任务和归档。
- `RelatedDocs/` 只负责相关资料索引和分析。

`product-design/` 中的 PRD 只记录产品执行内容和定性结论，不重复说明 `project-info/` 中已经定义过的项目规则、协作方式和边界约定。

## 编号用法

| 编号       | 模块                           | 用法                                  |
| -------- | ---------------------------- | ----------------------------------- |
| I1       | Index                        | 项目索引，记录各模块的位置和内容查找路径                |
| A1       | Architecture                 | 项目业务架构，记录产品、业务、角色、对象和流程             |
| U1       | User Learning Profile        | 用户学习阶段与沟通偏好，帮助 AI 按当前能力解释项目          |
| BS       | BrainStorming                | 头脑风暴，记录发散想法和早期探索                    |
| L1       | Log                          | 项目日志，按时间记录关键进展和阶段性变化                |
| G1       | Goal                         | 目标模块，通常作为 `Plan.md` 中的段落            |
| S1       | Summary                      | 项目介绍模块，通常作为 `Plan.md` 中的段落          |
| H1       | How                          | 达成目标的步骤模块，通常作为 `Plan.md` 中的段落       |
| T1       | Task                         | 任务模块，记录 Todo 与 Archive              |
| L2       | RelatedDocs                  | 相关文档模块，记录资料索引与具体分析                  |
| Research | Research                     | 调研文档模块，记录调研数据、访谈材料、用户画像资料、问题定义和分析过程 |
| PRD      | Product Requirement Document | 产品文档模块，记录战略层、范围层、里程碑，以及后续版本或功能 PRD  |

## 模块约定

- 模块可以是文件夹、文件，也可以是文件中的段落。
- `project-info/` 负责承载项目信息，后续源码、工程文件等放在 `project-info/` 之外。
- 当前项目中 `instruction`、`I1`、`A1`、`L1`、`Plan`、`T1` 使用 Markdown 文件承载。
- 当前项目中 `BS_BrainStorming`、`RelatedDocs` 使用文件夹承载。
- `I1` 负责帮助人和 AI 快速知道“内容在哪里”。
- `A1` 负责帮助人和 AI 快速知道“业务由什么构成”。
- `U1` 负责帮助 AI 快速知道 Allen 当前的编程能力、学习阶段和适合的沟通方式。
- `L1` 负责记录项目关键进展，不记录日志规则本身。
- `product-design/` 负责记录产品内容本身，不负责重复解释项目结构和协作规则。
- `Research1` 负责记录调研数据与分析过程。
- `PRD0` 负责战略层与范围层。
- `PRD1` 负责项目里程碑划分。
- 后续 `PRD` 用于记录具体版本或功能 PRD。

## 日志规则

日志记录在 `project-info/L1_Log.md` 中。

生成日志的时机：

- 用户主动说“生成日志”或明确要求记录日志时，记录一条日志。
- 小型任务状态刷新、任务归档、普通信息更新，不自动写入日志。
- 改动较大或 AI 判断有必要留痕时，先询问用户是否需要添加日志。
- 不需要在每次普通修改后自动生成日志。

日志格式：

```text
@YYYY-MM-DD HH:mm
当前进展简述：xxxxxxxxxxx
```

每条日志之间使用分割线分隔。
