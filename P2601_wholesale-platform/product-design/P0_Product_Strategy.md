# P0_Product_Strategy

## 项目定位

本项目从 0 到 1 搭建一个服装批发平台产品体系。

LIUHUAMALL 和过往 PRD 只作为案例资料，用于学习真实项目的思考过程、业务拆解方式和设计判断，不作为一比一复刻的功能说明书。

项目不是单纯练习 UI 页面，而是完整体验从产品定义、需求分析、交互设计、视觉设计到开发实现的过程，并把已有的买家端 Web 与移动端 UI 经验，扩展成能串联买家端、卖家端、管理端的完整产品设计能力。

## 作品集目标

- 展示对服装批发 B2B 电商业务的理解。
- 从买家端 UI 设计经验出发，补齐产品经理视角。
- 能说明买家端、卖家端、管理端之间的数据、流程和角色关系。
- 能把页面设计背后的业务目标、功能边界和后台支撑讲清楚。

## 参照对象

| 对象 | 说明 |
| --- | --- |
| 参考案例 | LIUHUAMALL |
| 官网 | https://www.liuhuamall.com/ |
| 平台类型 | 服装批发 B2B 电商平台 |
| 使用方式 | 参考其思考过程、页面组织和业务表达，不照搬功能和 PRD |
| 可观察重点 | 用户任务、业务流程、信息组织、三端协作方式 |

## 设计边界

- 不一比一复刻 LIUHUAMALL。
- 不照着旧 PRD 直接搬功能。
- 不把已有产品形态当作唯一答案。
- 优先保留从无到有探索产品的过程和乐趣。

## 核心设计主线

| 主线 | 关键问题 | 对应端 |
| --- | --- | --- |
| 买家如何找货 | 如何浏览、搜索、筛选、判断商品和供应商是否合适 | 买家端 |
| 卖家如何供货 | 如何发布商品、维护价格库存、处理询盘和订单 | 卖家端 |
| 平台如何治理 | 如何维护类目、审核商品、管理买卖双方和交易秩序 | 管理端 |

## 当前切入点

先从产品发现开始，明确目标用户、核心场景、真实问题和产品假设。

买家端仍然是优势切入点，但不直接从页面反推功能，而是先从买家的采购任务出发，再逐步推导需要哪些卖家端能力和管理端能力。

示例推导方式：

| 用户任务 | 可能需要的买家端能力 | 可能需要的卖家端/管理端支撑 |
| --- | --- | --- |
| 买家想快速找到合适货源 | 搜索、类目、筛选、商品卡片 | 商品发布、类目配置、商品审核 |
| 买家想判断供应商是否可靠 | 店铺信息、商品质量信息、联系入口 | 店铺资料维护、卖家资质审核 |
| 买家想确认价格和供货能力 | 商品详情、规格、起批量、询盘 | 价格库存维护、询盘处理、异常监管 |

## 近期产出方向

- 梳理目标用户、核心采购场景和待解决问题。
- 形成产品假设，再借助 LIUHUAMALL 和旧 PRD 做案例对照。
- 画出买家端、卖家端、管理端的端到端业务闭环。
- 定义 MVP 范围：优先覆盖商品、供应商、询盘、基础审核。
- 为后续 UI 设计、开发和测试提供统一产品依据。
