# PRD0_Product_Strategy

## S1. 文档定位

本文件用于定义当前项目的战略层与范围层。

战略层回答：为谁做、解决什么问题、平台是什么。

范围层回答：第一版要做什么、不做什么、哪些能力作为 MVP 优先完成。

调研数据、访谈材料、用户画像资料和用户分析过程统一沉淀在 `Research1_初次卖家侧调研&分析.md` 中；问题定义作为战略层结论沉淀在本文档中。

## 1. 战略层

### 1.1 项目背景

> 受疫情影响，海外采购商无法进入国内线下市场采购。流花市场希望通过线上平台促进跨境批发交易，并逐步补齐下单、支付、物流等交易闭环能力。

### 1.2 项目业务

流花跨境批发电商 B2B 项目。

| 用户角色 | 用户说明 | 核心诉求 |
| --- | --- | --- |
| 供应商小 B | 流花入驻批发供应商户 | 维持订单、拓展线上客户、降低经营压力、获得运营与跨境交易支持 |
| 渠道商小 B | 第三世界渠道商客户群，主要面向东欧、中东、南美、非洲市场 | 更方便高效地采购，降低空间距离、供应商可信度和交易风险带来的阻碍 |
| 平台方 | 流花市场及运营方 | 组织线上供给、触达海外买家、维护平台交易秩序，并探索后续服务与增值模式 |

### 1.3 核心问题

| 问题方向 | 结论                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ |
| 买家侧  | 疫情阻断线下采购后，买家需要更高效、更安全地找到可信货源，并完成跨境采购沟通。                                                                                        |
| 卖家侧  | 疫情封控导致海外客户无法线下采购，订单量骤减，需要一个渠道能促成与买家之间的交易。                                                                                      |
| 平台侧  | 平台要解决的不只是搭建线上商城，还包括供给组织、买家触达、信任建立、基础服务和跨境场景适配。<br>但不同卖家的参与意愿、客户储备、数字化能力和信任状态差异很大，不能只用单一卖家画像描述，需要建立完善的特征标签以精细化的运营，更能解决买家、卖家的问题。 |

### 1.4 问题定义

问题定义基于调研材料和用户分析收敛而来。这里先说明痛点，再补充问题成因，并给出后续可进入需求池的解决方向。

| 问题定义                                                                                                                       | 主要用户画像 | 解决方向                                    |
| -------------------------------------------------------------------------------------------------------------------------- | ------ | --------------------------------------- |
| 1. 商城客户骤减，供应商们的订单也少了很多。因为疫情国外采购商无法到线下来采购。采购商希望能更方便高效地采购，不受空间距离所影响。                                                         | 采购商    | 商品浏览、搜索、筛选、商品详情、店铺展示、询盘入口               |
| 2. 线上商城对供应商没有足够的吸引力，参与人数不多。因为供应商们没有充分了解到线上商城的政策，担心仅凭自己无法运营好线上商城。供应商希望能有专业运营团队帮忙指导或代运营。                                     | 供应商    | 入驻说明、平台规则说明、上架引导、模板化商品发布、运营指导、代上传/代维护服务 |
| 3. 商城客服人员收到大量银行卡被冻结的反馈需要处理，影响到了商城的跨境交易。因为公安部为了防止洗钱活动，经由公账户汇款至个人卡这类交易就会被冻结账户。供应商希望能更方便地进行跨境交易。                              | 供应商    | 跨境交易规则说明、合规收款说明、常见问题知识库、客服支持入口          |
| 4. 供应商不愿意提供新款服装的照片，这将影响商城服装的上新速度。因为供应商们担心自己新设计的版式会被同行抄袭。供应商希望自己的服装版式独一无二，版权受到保护。                                           | 供应商    | 图片水印、图片权限控制、商品图片保护提示、原创/版权说明            |
| 5. 商城客服人员经常会被供应商问到一些法律、财税相关的问题，触及到知识盲区，使得商城无法很好地给供应商提供服务。因为供应商们在做跨境业务时常常会有不了解的地方，转移到线上商城这一新领域后更是如此。供应商们希望有专业的法律人士来解答自己的困惑。 | 供应商    | 法律财税知识库、咨询入口、客服分流、专家咨询服务                |
| 6. 在宣传初版线上商城后，吸引到的采购商并不多。因为采购商对供应商的服务与服装质量没有一个清晰的认知，不敢轻易下单。采购商希望在采购的过程中安全可靠，没有风险。                                          | 采购商    | 店铺信息、供应商资质、商品真实性展示、交易保障说明、试点商户案例、效果反馈   |
| 7. 商城工作推进变得困难，很多供应商对商城的信任度降低。因为疫情使商城客户减少，供应商生意变差，没有赚到钱还要交租金，心理不平衡。档主希望商城对这种局面做出及时有效的对策，减少自己的损失。                            | 供应商    | 政策沟通、阶段性扶持说明、试点商户案例、运营效果反馈、商户沟通机制       |

### 1.5 平台定位

本项目定位为面向服装批发场景的跨境 B2B 平台。

核心价值是帮助海外买家更高效地找货、判断货源、发起沟通，同时帮助流花供应商更稳定地展示供货能力、获得采购线索，并让平台具备基础审核与治理能力。

### 1.6 设计原则

- 先围绕“找货、判断、询盘、供给组织”形成最小闭环。
- 买家端优先降低采购决策风险，而不是一开始追求完整交易复杂度。
- 卖家端优先降低参与门槛，并区分不同主动性与经营状态的卖家群体。
- 平台端优先建立基础审核、类目和供给治理能力。
- 支付、物流、售后、代运营等复杂服务先作为后续阶段能力，不在 PRD0 中提前定案。

## 2. 范围层

### 2.1 MVP 核心闭环

第一版优先验证：

1. 买家能够找到商品，并判断是否值得发起询盘。
2. 卖家能够展示商品，并接收、处理买家询盘。
3. 平台能够完成基础类目、商品和卖家审核。

### 2.2 功能范围总览

| 端 | 功能模块 | 范围判断 |
| --- | --- | --- |
| 买家端 | 商品浏览与搜索筛选 | MVP |
| 买家端 | 商品详情与店铺信息 | MVP |
| 买家端 | 询盘与联系入口 | MVP |
| 买家端 | 订单创建与订单列表 | 候选 |
| 买家端 | 支付、物流、售后 | 非 MVP |
| 卖家端 | 商品发布与商品管理 | MVP |
| 卖家端 | 价格、库存、起批量维护 | MVP |
| 卖家端 | 询盘处理 | MVP |
| 卖家端 | 订单处理 | 候选 |
| 管理端 | 卖家管理与资质审核 | MVP |
| 管理端 | 商品审核 | MVP |
| 管理端 | 类目管理 | MVP |
| 管理端 | 订单监管与复杂运营能力 | 非 MVP |

### 2.3 非 MVP 暂缓项

- 支付能力
- 物流履约能力
- 售后能力
- 复杂订单异常处理
- 完整代运营、陪跑服务和法律财税支持等服务模式

### 2.4 当前范围判断

当前 MVP 更适合先完成“商品 + 店铺判断 + 询盘 + 基础审核”的撮合闭环。

订单能力保留为候选范围。如果后续希望更强调交易闭环，可以纳入第一版；如果当前更强调找货和供货撮合效率，则订单、支付和物流应放到后续版本。
