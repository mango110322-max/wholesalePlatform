# D4_Product_Image_Plan

## 文档定位

本文件用于设计下一阶段的商品图片能力。

当前结论：

```text
下一阶段先做商品主图字段 MVP。
暂不做真实文件上传。
暂不拆 product_image 表。
```

最小目标：

```text
product 表加 main_image_url
卖家新增商品时填写图片 URL
卖家 / 管理端 / 买家端列表展示主图
```

## 为什么先做商品图片

在服装批发平台里，图片不是装饰，而是商品表达的核心信息。

买家判断一个服装商品是否值得继续看，通常先看：

- 款式图片。
- 颜色和版型。
- 面料质感。
- 是否像真实档口或真实货源。
- 是否适合自己的销售渠道。

如果先做商品详情页但没有图片，详情页会更像“商品资料页”，不像真实电商商品详情。

所以当前顺序建议是：

```text
商品主图能力
  -> 商品详情页
  -> 询盘 / 下单入口
```

## 当前不选择复杂方案的原因

### 暂不做真实上传

真实上传会引入更多技术点：

- 前端文件选择和预览。
- 后端接收 multipart 文件。
- 本地文件存储或对象存储。
- 文件大小、格式、访问权限。
- 图片压缩、裁剪、水印。
- 文件 URL 回写数据库。

这些能力很重要，但会让当前学习重心从“商品链路理解”跳到“文件系统和对象存储”。

当前更适合先用图片 URL 输入，先理解字段如何穿过三层架构：

```text
前端表单
  -> 前端 API
  -> 后端 DTO
  -> Entity
  -> Mapper SQL
  -> product 表
  -> 三端列表展示
```

### 暂不拆 product_image 表

真实商城通常会拆图片表，例如：

```text
product_image
  id
  product_id
  image_url
  image_type
  sort_order
```

但当前只需要一张主图，直接放在 `product` 表里更容易理解。

等后续需要多个图片时，再拆表会更自然：

| 阶段 | 方案 |
| --- | --- |
| 当前 MVP | `product.main_image_url` |
| 后续多图 | `product_image` 表 |
| 后续详情页 | 主图 + 多张详情图 |
| 后续真实运营 | 上传、压缩、水印、防抄版 |

## MVP 字段设计

在 `product` 表新增字段：

| 字段 | 类型 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `main_image_url` | `VARCHAR(500)` | 否 | `NULL` | 商品主图 URL |

选择允许为空，是为了降低第一版迁移成本：

- 旧数据没有图片也能继续展示。
- 卖家可以先保存商品，再补图片。
- 前端可以用占位图展示无图商品。

## 三端展示目标

### 卖家端

卖家端需要看到：

```text
这条商品记录有没有主图
主图和商品名称、价格、库存是否对应
```

列表中建议显示小缩略图。

### 管理端

管理端审核时需要看到：

```text
商品图片是否明显不合规
图片和商品名称 / 类目是否匹配
```

当前阶段只做展示，不做复杂审核原因填写。

### 买家端

买家端需要优先看到图片。

商品卡片建议从现在的文字列表升级为：

```text
主图
商品名称
价格
库存
起批量
```

## 占位图策略

如果 `mainImageUrl` 为空或图片加载失败，前端可以展示一个简单占位区域：

```text
暂无图片
```

当前阶段不需要专门设计图片素材，占位图用 CSS 做即可。

## 与审核状态的关系

当前 MVP 中，图片不单独审核。

图片作为商品内容的一部分，跟随商品整体审核：

```text
卖家新增商品并填写主图
  -> audit_status = PENDING
  -> 管理端看到图片并审核商品
  -> APPROVED / REJECTED
```

后续如果要更真实，可以考虑：

| 能力 | 说明 |
| --- | --- |
| 图片变更后重新审核 | 商品已上架后，如果卖家修改主图，需要重新进入审核 |
| 图片审核记录 | 记录哪张图被谁审核、什么时候审核、审核结果 |
| 水印 | 对卖家上传图片加平台水印或档口水印 |
| 防抄版提示 | 针对服装批发行业的图片盗用问题，做前端提示或图片处理 |

## 下一步实现顺序

建议下一轮编码按这个顺序做：

```text
1. 改数据库脚本和字段说明
2. 改后端 Entity / DTO / Mapper / Service
3. 改前端类型和新增商品表单
4. 改卖家 / 管理端 / 买家端展示
5. 启动后端和前端，走一遍新增 -> 审核 -> 上架 -> 买家展示
```

验收标准：

| 场景 | 预期结果 |
| --- | --- |
| 卖家新增商品并填写图片 URL | 数据库保存 `main_image_url` |
| 卖家商品列表 | 能看到商品主图 |
| 管理端待审核列表 | 能看到商品主图 |
| 管理端审核通过后卖家上架 | 状态流转不变 |
| 买家商品列表 | 只展示符合条件的商品，并显示主图 |
